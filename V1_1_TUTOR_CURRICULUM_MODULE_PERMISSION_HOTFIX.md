# V1.1 Tutor Curriculum and Module Permission Hotfix

## Corrected defects

1. The AI Curriculum Import wizard performed unrestricted reads of `programmes`, `courses`, and `modules`. Hardened Firestore rules correctly rejected those reads for tutors.
2. Records generated by the importer omitted `ownerUserId`, `createdByUid`, `assignedTutorIds`, and `institutionId`, despite those fields being required by the academic catalogue security model.
3. Manual module creation could pass an undefined `institutionId` from a legacy tutor profile. Firestore rejects undefined values before evaluating security rules.

## Corrections

- Curriculum comparison and import now query only records owned by or assigned to the tutor. Administrators remain institution-scoped.
- Imported programmes, course units, modules, and import audit records include ownership and tenant metadata.
- Module creation removes undefined values and creates the final document, including its ID, in one write.
- Added regression tests for scoped catalogue reads, ownership metadata, and undefined-field sanitization.

## Deployment

Run:

```powershell
npm install
npm run release:check
firebase deploy --only firestore:rules,firestore:indexes,hosting
```

Then sign out and sign in again before testing the tutor curriculum import and module creation pages.
